1 Executive Summary & Business Scope

Business Scenario: DevPulse Labs is an independent software engineering house specializing in static code analysis, software architecture auditing, and automated engineering metrics. Historically, their analytics operated purely as internal CLI utilities.

The Core Objective: Package and monetize DevPulse’s proprietary code analysis engine as a commercial, public-facing API Product for third-party developer teams, engineering managers, and CI/CD pipelines.

Core Features Delivered: Tiered API key authentication (x-api-key), Sliding-Window rate limiting with HTTP 429 and Retry-After headers, OpenAPI 3.0 contract specification, interactive Swagger UI portal (/docs), and dual-version support (/api/v1 deprecated vs /api/v2 modernized production).

5 Special Constraint: Rate Limiting Comparison Benchmark

To satisfy the internship Special Constraint, two rate limiting algorithms were implemented, benchmarked, and evaluated under identical burst load profiles:

Metric / Attribute Approach A: Fixed Window Counter Approach B: Sliding Window Counter Significance & Decision
Boundary Burst Vulnerability FAILS (Allows 200% Limit) PASSES (Capped at 100%) Fixed Window allows 40 requests in 2 seconds across boundary.
Burst Leakage in 2s Gap 40 requests allowed 21 requests allowed Sliding Window strictly protects downstream databases.
Average Decision Latency 373.1 nanoseconds 561.3 nanoseconds Both sub-microsecond overhead (< 0.001 ms).
Throughput Capacity 2,679,959 ops/second 1,781,515 ops/second Negligible CPU overhead difference.
Memory Complexity O(1) (2 fields per tenant) O(1) (3 fields per tenant) Scales to millions of concurrent API keys in memory.
Production Selection Rejected due to boundary exploit SELECTED FOR DEVPULSE Industry standard (Stripe & Cloudflare architecture).
Architectural Conclusion: While Fixed Window is slightly simpler, its vulnerability to boundary bursts (2x contracted capacity) poses a severe DDoS risk. Sliding Window Counter provides strict fair-use guarantees at near-zero performance cost.

7 Validation Evidence: Problems Found & Fixed

# Component Problem Diagnosed Root Cause Fix Implemented & Verification
1 Benchmark Harness Simulation allowed 20/20 on both T59 and T61 within Fixed Window. Base time was not aligned to 60s window boundary. Introduced ALIGNED_WINDOW_START math. Boundary burst accurately reproduced.
2 Performance Loop ReferenceError on variable during 10k benchmark. Variable name mismatch during boundary refactoring. Normalized timing variables. 10,000 iterations ran cleanly in 5.61ms.
3 Swagger UI Assets Direct hit to /docs missing CSS styling without trailing slash. Express routing mount behavior in swagger-ui-express. Mounted at both /docs and /api-docs; assets render perfectly.
4 Rate Limiter Headers Retry-After occasionally rounded down to 0s. Clock millisecond rounding error. Added Math.max(1, Math.ceil(...)) guarantee; returns integer seconds.
